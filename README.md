**[跟单能力空间与组合研究](project/CAPABILITY-SPACE-AND-COMBINATIONS.md)** 已归纳交易复制、交易者能力研究、市场情报、AI辅助决策四种不同目标，以及12项可发展能力、6组互补组合、参考成品、失败案例与证据缺口。该图谱用于帮助用户从一句简单想法发展目标、比较价值，**不代表用户已选择全部能力，不预设立即开发或固定研究顺序**。下一步可比较组合是否提供单项能力没有的增量，再按当前意图选择工具调查、规划或实施。

## 2026-11-10｜最新表达要求：专业研究与讲人话同时进行

用户以普通话提出跟单想法，AI 负责理解、延伸、搜索、比较和验证，再以容易理解的语言说明“发生了什么、为什么值得注意、对跟单有什么用、哪些还不能确定”。专业研究不能被省略，但不应直接把论文、术语、源码或方法框架原封不动交给用户；需要专业名词时顺带解释。用户的反馈反过来改变后续研究问题，而不是每次都以固定模板开始。详见 [AI 跟单工作指令](prompts/AI-跟单研究指令.md)。



## 2026-11-10｜最新协作修正：从简单表达发展目标，而非再设置固定研究入口

这次修正补足此前“从研究哲学纠偏到真实案例优先、再到钱包/软件参数优先”反复固化入口的问题：**用户一句话不一定已经是成熟的执行任务**。AI 要先辨认这是意图探索、方案比较、疑问解答、调查还是实施；当目标还在形成时，主动发展几种合理的专业理解与方案，允许用户通过反馈逐步收敛；当任务已经明确且获授权时直接完成并核验。**不默认先做真实案例、不默认先写计划、也不默认先做知识研究。**

钱包类型、捆绑、买卖转仓、跟法、软件参数与俄语实操材料仍是重要业务能力，但不是每轮强制顺序。复杂问题可以反复推演和检验遗漏，直到有助于下一步决策；简单问题不用形式化流程。旧项目知识按需使用，旧文档的“默认/每轮/唯一优先”若与此处冲突，以此处最近用户确认的目标理解为准。详细见 [AI 跟单工作指令最新修正](prompts/AI-跟单研究指令.md)。此处是文档级修订，不代表独立评测已经完成。


## 2026-11-10｜业务纠偏：钱包、捆绑、买卖、跟法和软件参数优先

本节覆盖旧入口中偏向“AI 认知体系/专业词汇/宏观路线图即进度”的默认倾向；**不是删除既有研究**。`ai-d` 的专业推理只作为后台辅助，不替代跟单业务成果。

**需要研究完整跟单实操时的典型业务链（不是所有请求的默认顺序）**：公开候选钱包发现 → 行为类型及买/卖/转仓复盘 → 捆绑交易与疑似关联钱包的证据区分 → 选择要复制的交易子集 → 对应具体软件的买额/过滤/跟卖/止盈止损/滑点/费用设置 → 只读模拟/前向记录 → 失败与收益复盘。

**最近可用的实操依据**：[Mark 原视频字幕参数还原](knowledge/copytrading-ru/01-mark-video-study.md) 与 [钱包→跟法→软件设置操作对照](knowledge/copytrading-ru/02-wallet-selection-specific.md)。现有字幕明确记录了单币只买一次、最低市值、目标钱包最低买额、分批止盈和 Copy sells 等**演示参数**；不同配置片段无法可靠绑定同一个钱包或十日收益，不能拼接为盈利案例、不能照抄做实盘参数。

**进入实操研究、调查或产品建设时，一次工作应尽量改变一件实事**：解释并分类某个有来源的钱包/交易；识别一条捆绑/转币/接收后卖出的证据或反例；还原一组具体软件设置及互斥组合；复现一次可检查的工具输出；或在前向纸上记录中比较一个事前冻结的跟法。没有这些增量就报告缺口、切换数据/工具入口，不扩写 AI 哲学。

**目前状态**：有既往视频字幕与供应商历史快照、离线工具；没有完整地址与配置一一绑定、没有本轮主网签名/真实可见时间及样本外跟单净收益。当前允许只读、纸上模拟、源码和资料核查；不下单、不授权钱包、不支付。详细执行参见 [第一轮只读案例](operations/FIRST-REAL-CASE.md)。

## 2026-11-10｜当前工作方式：围绕整件事作判断并推进

本节替代历史文字中把知识研究、知识激活、固定领域覆盖当作默认起点的要求。历史资料保留供按需使用；不要把本节再扩成一套每轮必填的框架。

用户用普通语言表达想法，AI 负责理解要做成的事情、现有条件和未说清但影响结果的因素。先比较有实质区别的办法，借鉴做过同类事情的专家、成熟产品与真实案例，然后在授权内行动并复核。研究、教学、配置、调查、开发都是可选手段；不默认先写报告或先写代码。

遇到小问题时，不以完成它替代整个目标。必要时向上追问它属于哪个业务决定、为何反复出现，向下检查实际操作、参数、数据或实现，横向寻找其他行业处理相似问题的成熟办法。发现重要原因后要回到原任务，说明它改变了什么选择；没有影响的分支可以停止，不无限扩题。

外部搜索由具体疑问驱动。把普通说法转换成该行业从业者使用的术语、俗称、工具名称和失败现象，按需使用中英俄等语言及关键词组合。找完整做事过程、成功与失败案例、评论中的异议、成品和原始说明；不能只搜支持原判断的材料。跨行业借鉴要说明相似之处、不同条件、准备怎么用和怎么检查，不能因名词相近直接照搬。

重要或成本较高的工作，先比较方案并检查遗漏与失败可能；每次修订须解决一个具体疑问，不机械循环固定次数。可逆的小规模尝试可用于澄清方案。判断已足以支持下一步时就行动，不等所有知识齐全。

表达先讲具体对象、观察、选择、做法与结果，再解释必要原理及适用条件。不能只换成口语而仍交付概念目录。专业程度看是否改善判断、减少返工、完成有用成果，而非术语、资料量或文件量。新认识与灵感可以有独立价值，但须关联具体用途或可检验的问题。

现有知识是参考，不是强制流程；ai-d 自身也接受实际任务反馈的修正。文件更新不代表模型永久学会，也不代表运行时已集成。原有权限、资金、签名及费用边界继续有效。

## 你的问题就是项目的研究入口

- 一份 Froggy 导出里为什么有些高 PnL 钱包应该跳过？
- 同一钱包为什么不能复制它的全部交易？如何按买入金额、市值和持仓行为拆解？
- 多钱包属于同一组织、共享工具，还是独立交易者？资金、Token 和实际成交要如何区分？
- 新钱包接收 Token 后卖出时，原钱包是否仍值得跟踪？
- 该钱包能盈利，为什么跟随者可能因为执行延迟、费用和价格冲击而亏损？
- 初选的钱包十天之后还有效吗？没有交易的地址怎样处理？跟单盈亏与其他交易如何拆账？

## 来源与能力分工

**研究优先级**：俄语实操视频、原始文档、可检查的复盘与反例 → 项目特有的专业假说 → 成熟软件上的验证 → 后续修订。

**已成熟的软件**：Froggy 用于批量发现与筛选；GMGN/OKX/Blix 等用于交叉核查交易与资金；监控器用于观察买卖/转账。功能以其真实可见版本为准，不自己重复做一套交易终端。

**按需调用的市场知识**：[原通用 Meme 知识入口](knowledge/meme/README.md)、[原 Blix 专业知识](https://github.com/sunshihao001/grok/tree/blix/knowledge)、[ai-d 专业研究方法](https://github.com/sunshihao001/ai-d)。不复制十二域/专家制度作为默认过程。

## 事实边界

资料阅读≠实际运行。俄语作者操作演示≠稳定盈利。供应商 ROI、Win Rate 和 PnL≠自己的可复制收益。同槽/同源资金≠共同控制。仅进行只读调查与纸上跟单研究；不授权交易、签名、付款或提交私钥。
