# 跟单能力空间与组合研究｜开放目标、现有基础、候选价值（2026-11-10）

> **性质：领域认知与选择依据，不是新架构、强制路线、立即开发清单或盈利声明。**
>
> 用户原始问题：“跟单究竟能够发展出哪些能力？” 允许从一句简单想法，逐渐发展出不同目标；不默认“只做交易 Bot”“先找真实案例”“先做知识系统”或“必须全部集成”。AI 应把新可能性作为**候选**，通过专业知识、成熟方案、实际反馈帮助用户选择，不能悄悄替换既有目标。
>
> 范围：Solana Meme 跟单研究。现阶段只读调查、离线分析与纸上验证；无真实交易、签名、付款或私钥操作。信息截至 2026-11-10 的仓库/公开项目阅读，不代表所有第三方项目都已安装实跑。

## 1. “跟单”至少有四种不同目的

| 目的 | 用户实际得到什么 | 不能自动等同 |
| --- | --- | --- |
| A. 交易复制与执行 | 根据钱包买卖信号配置跟单、独立退出、管理成本与风险 | 源钱包盈利 ≠ 跟随者盈利 |
| B. 交易者能力研究 | 理解不同钱包的选币、入场、加仓、转仓和退出方法，提取候选交易规则 | 识别一种历史风格 ≠ 发现稳定策略优势 |
| C. 市场情报与风险判断 | 利用钱包行为、资金网络、代币库存、群体信号发现机会或识别风险 | 多钱包同买 ≠ 独立共识或共同控制 |
| D. AI 辅助研究与决策 | 用简单自然语言让 AI 选择问题、查证据、比较工具/方案、解释/试验/复盘 | 模型解释/生成策略 ≠ 正确归因或经过验证的收益 |

四者可以独立有价值，也可以局部组合。用户当前说“跟单”时，不可由此自动推断已经选择哪一项作为长期唯一目标。

## 2. 12 项可能发展出的能力：从用处回看技术

| 编号/能力 | 真正解决的问题 / 典型产物 | 已有入口与目前证据状态 |
| --- | --- | --- |
| 01 跟买、跟卖和独立退出 | 固定额/比例复制、分批退出、止盈止损、镜像仓位管理；产物是可明确复核的软件配置 | GMGN/OKX 官方功能说明；[本仓钱包与设置卡](../knowledge/copytrading-ru/02-wallet-selection-specific.md)。**DOC / SOURCE_READ；非本仓真实账号操作验收** |
| 02 钱包筛选与交易画像 | 区分 Sniper、低频波段、高频/套利、执行/转仓、DEV/KOL候选；识别一个钱包的不同交易子集 | [Mark × Froggy 原字幕研究](../knowledge/copytrading-ru/01-mark-video-study.md)；视频演示不是独立验证 |
| 03 入/出场与可复制性 | 区分源交易时间、信号首次可见、成交报价、费用、无法成交及退出条件；产物是可复制性研究 | [RU-003 深层研究](../research/RU-003-deep-study.md)、[CopyCheck](https://github.com/michal490/copycheck)；对照样本/方法不构成一般因果结论 |
| 04 钱包关系与资金追踪 | 买入→Token转移→接收地址卖出→可能跨Mint；处理Owner/Token Account/池/公共枢纽 | [共享Mint案例001](../research/SHARED-CASE-001-BLIX-TO-GENDAN.md)、Blix 既有只读研究；本仓尚无完整实跑多跳链 |
| 05 捆绑/疑似关联筹码 | 区分真实 Jito Bundle 与同槽/同资金源/疑似关联持仓，检查集中度分母和后续派发 | [Jito 原始说明](https://docs.jito.wtf/)、[GMGN 标签说明](https://docs.gmgn.ai/cn/te-se-tu-biao-ding-yi)；同槽或供应商标签不足以证明同控 |
| 06 多钱包独立信号 | 判断多个地址是否独立参与，识别重复投票、共用服务、拥挤信号 | [Million](https://github.com/Kelows/million) README 描述了 cluster 合并和 consensus；**作者功能描述，尚未在本仓验证精度** |
| 07 钱包↔代币双向发现 | 钱包找到新Mint；从Mint早期参与者进一步找到钱包；产物是新的观察候选 | Million 的双向爬取思路，结合 GMGN/Froggy 的发现能力；候选发现不等于超额收益 |
| 08 发行、库存与风险预警 | 关注流动性、池/Holder混淆、集中库存、流入池的潜在卖压、开发者历史等 | [共享Mint案例001](../research/SHARED-CASE-001-BLIX-TO-GENDAN.md) 已从历史供应商快照排除池相关“巨鲸”；不能据此断定其他Holder身份 |
| 09 策略提取与条件过滤 | 从某钱包某种买卖风格形成事前定义的规则，不全量照抄 | [RU-003](../research/RU-003-deep-study.md) 和 [Solana Copy-Trading Simulator](https://github.com/mpusio/solana-copy-trading-sim)；**历史优化容易过拟合** |
| 10 回测、纸上前向与影子对照 | 比较原样跟随/交易子集/独立退出/被跳过的信号，并记录未成交、失败与全部成本 | [ScreenerBot](https://github.com/farfary/ScreenerBot)、[dexterm](https://github.com/dexterm-xyz/dexterm)、[Million](https://github.com/Kelows/million)；本仓有离线反例，缺前向真实信号账本 |
| 11 AI 自然语言调查和工具协同 | 用户一句话查询“这个钱包怎么样/为什么没买/还有哪些方向”，AI 按需调研、比较、解释或执行只读工具 | Million Agent/MCP、dexterm 只读 AI 分析入口、[ai-d](https://github.com/sunshihao001/ai-d)；不等于当前 Gendan 已部署 AI 运行时 |
| 12 研究结果积累与自我修正 | 保留错误假设、有效条件、失败样本和决策变化，不将资料数、参数数当进步 | [Gendan 台账](../research/ACTIVE-LEDGER.md)、[ai-d](https://github.com/sunshihao001/ai-d)；跨任务质量增益未独立验证 |

**解释原则：** 分类是用途地图，不是十二个独立模块或十二个建设阶段；多个能力可能由同一个成熟终端解决，部分能力仅需研究方法而无需新代码。

## 3. 比单独功能更值得深入的“能力组合”（全部为待验证假说）

| 组合 | 为什么可能有额外价值 | 最小可观察比较 | 典型失败/反证 |
| --- | --- | --- | --- |
| 钱包画像 + 可复制性（02+03） | 历史高收益与普通跟随者可获得收益可能不同 | 同一批源交易，对比原钱包成交与首次可见报价/成本/退出；保留无法成交单 | 仅优化历史赢家、没有时点证据、源钱包本身不完整 |
| 关联关系 + 多钱包信号（04+06） | 排除疑似同一操作者多个地址导致的“虚假共识” | 同一时间窗对比地址数量与经证据支持的独立群体数量；比较后续风险与信号表现 | 公共CEX/路由器误归因、把候选当确定同控 |
| 钱包↔Mint双向发现 + 风险过滤（07+08） | 发现机会同时排除基础设施账户、薄池与异常库存 | 固定 T0 后记录候选母样本、过滤原因、被跳过的Mint后续表现 | 只报告通过的币、过滤造成幸存者偏差 |
| 转仓接收者追踪 + 跟卖策略（04+01） | 源钱包无直接卖单，不等于没有后续代币派发/出售 | 检查 A 买→B收→B卖是否有逐笔证据；比较只盯A卖单与扩展监控的风险事件覆盖 | 同Owner内部转仓、普通托管、只凭转移判同控 |
| 策略提取 + 前向/影子对照（09+10） | 判断“只复制某类交易/独立退出”是否优于原样跟随 | 事前冻结规则；同市场同成本记全量、过滤组、被跳过组和失败 | 参数在结果揭晓后修改、价峰当成交价、前向样本不足 |
| AI 交互 + 成熟工具（11+01/04/10） | 从一句口语直接获得钱包调查、配置含义、纸上结果和失败原因 | 与手工流程对照：时间、漏项、误导性判断、用户重复指挥次数 | AI 臆造工具结果、权限扩大、数据陈旧、增加额外操作负担 |

这些组合是**研究价值候选**，不是已证明优于单项能力。市场环境变化时，可能应停止或改变某种组合。

## 4. 高价值反例：复杂系统不代表交易优势

- [ricoboost/meme-coin-trading-bot](https://github.com/ricoboost/meme-coin-trading-bot) 作者声明多钱包聚合策略**历史回测有效、真实运行亏钱**。其 [策略复盘](https://github.com/ricoboost/meme-coin-trading-bot/blob/main/docs/STRATEGY.md) 将拥挤跟单、滑点、幸存者偏差、优先费、退出困难列为原因。这是作者自述故障经验，不是普适统计结果。
- [Yuno Issue #10](https://github.com/yuno-research/solana_copy_trading/issues/10) 记录历史排序/优化后在新时间窗仍未盈利的研究困境；复杂优化不应替代样本外评价。
- [dexterm](https://github.com/dexterm-xyz/dexterm) 自述部分策略自动化仍处实验期，并明确指出公开预设策略尚未证明有效。
- [CopyCheck](https://github.com/michal490/copycheck) 用两个地址的实际记录区分入/出场价格造成的毛收益差异；无法仅凭对照确认 B 的复制意图、真实滑点因果或净收益。它说明**先诊断差异发生在哪个环节，再决定优化速度还是退出**。

## 5. 与既有工程的关系及现实状态（不是新的集成承诺）

- **Gendan 本仓**：已有 Mark/Froggy 字幕研究、钱包行为与策略冲突分析、只读 V0.2 离线引擎和历史供应商快照检查；README 曾记载 22 项离线测试通过，**本轮未重跑**；缺真实钱包持续观测、T_seen、签名级资金链和前向跟单净收益。
- **Blix/Meme**：已有市场、Mint、钱包角色和证据工程的专业认识，部分能力仍在未合并 PR 或离线验证状态；不能把研究成果直接视为 Gendan 的实时运行接口。参考 [现有跨项目审计](BLIX-GENDAN-SHARED-CAPABILITY.md)。
- **ai-d**：提供“理解简单表达—发展目标—按条件选择研究、规划、行动”的协作知识，不将任何固定研究入口覆盖 Gendan 的业务目标。AI 协作提升仍需对照任务检验。
- **成熟软件/开源产品**：优先判断“直接使用／有限设置／轻量组合／确有缺口才开发”，每项记录 DOC、SOURCE_CODE、OFFLINE_TEST、REAL_READ_ONLY 或 NOT_RUN，不混淆作者主张与本仓验收。

## 6. 继续推进时可以比较的三个切口（不规定唯一顺序）

**选项 A｜从使用者目的重新判断。** 比较“直接跟单收益”“学习交易者的策略”“做钱包与市场情报”“AI 辅助决策”各自要解决的真实问题、投入和取舍。适用于目标还未收敛时。

**选项 B｜检验具有互补性的两种组合。** 优先考察「关联关系 × 群体信号是否独立」和「钱包行为 × 跟随者入出场/退出」，用已有 Blix/Gendan 资料与成熟源码对照，找出**单独能力无法回答的问题**，再确定需要何种新数据。适用于当前已有充分领域知识但不清楚哪些组合真正有增量时。

**选项 C｜拿一个公开钱包或 Mint 做小范围真实只读验证。** 检查来源签名、行为、转仓、当时市场条件以及软件可见字段；若出现可观察的新信号，冻结纸上跟随规则并记录全部结果。适用于已经选定一个明确业务判断且有数据入口时；参考 [第一轮操作卡](../operations/FIRST-REAL-CASE.md)。

**目前建议：先做 B 中的“组合价值与现有成品覆盖对照”，随后选一个能被真实数据区分的组合进入 C。** 原因：资料库已经较多、V0.2 已有离线工具，当前最需要证明新组合是否提供单项能力没有的信息；直接建设完整 AI 交易系统价值尚不明确。这是可撤销的**本轮研究判断**，不是用户承诺或永久优先级。

## 7. 什么结果才算此类研究有了实质进步

- **认知增量**：提出并证实/证伪一个原先无法区分的解释，例如“多个钱包其实是一个独立信息源”。
- **决策增量**：改变候选钱包选择、信号处理、参数方案或应不应该进入纸上测试的判断，并说明为什么改变。
- **产品/操作增量**：复用一个确实可用的成熟功能、完成可查的只读调查或运行可靠的纸上实验。
- **效果增量**：在未知结果的未来观察中，比较基线与候选方式的费用后表现、漏报和失败；不能由单例或合成实验宣称策略盈利。

**本文件本身仅完成能力空间的组织与研究入口保存，不构成以上交易效果的实现。** 下一轮可以推翻本文件的推荐，不能拿“文件数量、专家数量、概念数量”当成项目进度。
