# 03｜市场认知的证据工程：我们看到的市场不等于完整市场

> 源于旧 D10/D11 与 2026-11-09 Blix 的样本/标签生成错误研究。此章保护整个通用 Meme 知识系统不被误记与选择偏差污染，而不只是「保守说 UNKNOWN」。

## 六个必须分别记录的对象

1. **真实世界事件**：链上某种状态是否真的发生。
2. **采集覆盖**：哪个索引器/RPC/采集程序、在什么 Slot 和范围看见哪些事件。
3. **解析分类**：把原始交易解释为 swap/transfer/LP/买入/卖出是否正确。
4. **软件展示**：GUI 的 smart money/Top Trader/bundler/Dev-related、ROI 等标签与分母；平台陈述不是协议事实。
5. **研究解释**：为什么发生这些行为、是否同一经济组织，属于可反证的推论。
6. **独立后验结果**：后续价格/群体/流动性/策略表现，必须保证事件可得时点和样本成熟。

链上数据真实存在，不代表**采集器看得完整**；两家 UI 显示相同标签，不代表两家独立证明身份。

## 四种时间不能合成「交易时间」

- \`event_time\`：链上 Slot/blockTime 或相关区间。
- \`recorded_at\`：索引器/数据库第一次实际记录时间。
- \`available_to_user_at\`：研究者当时真正能收到并理解事件的时间。
- \`outcome_matured_at\`：研究的收益/毕业/失败标签何时具备判断资格。

晚到的补查数据可以修复历史解释，却不允许伪造「当时可提前发现」。延迟时间和源可信度都与价值有关。

## 2026-11-09 的高价值反例：从采集器错误生成「市场规律」

Blix 新近知识报告对一个公开 Meme 采集/标签项目的源码与离线条件进行了审查：某些早于观察期结束的缺 K线状态被写成未来 24h/3d 负标签，之后常规队列不再重访。**这是上游源码路径及离线重现记录，不是本仓库对真实全市场概率的测量**。

同一时期香港公开的 RED-COHORT 研究在 2026-10 修订时说明：其 buyer records 包含 sell，且遗漏许多真实买入；早期的群体效果数值因此撤回。**不能继续引用被撤回的旧收益/效应数字。**

这意味着三类看似精确的研究结论可能一起失效：
- **入选总体错**：只研究热门/迁移/可被收录的 Mint，失败币从母样本消失。
- **事件分类错**：把卖出当买入、Token transfer 当交易、同 signer 当 buyer。
- **结果时间错**：事件尚未成熟，就标为 24h 失败；或用未来高点计算历史可交易收益。

关键知识不是「完全不相信任何数据」，而是**明确每一种数据可以回答多大的问题**。部分样本可以支持样本内机制描述，不能自动支持全市场频率、因果效应或事前可执行策略。

## 反证不是所有现象都否定

| 最初解释 | 合理竞争解释 | 最有鉴别力的额外证据 |
| --- | --- | --- |
| 「相同时间买入 = 一伙人」 | 共用自动交易模板/热门事件 | 资金/Token 分工、真实多次重复、公共 Hub 负例 |
| 「持仓下降 = 出货」 | 同 owner 转仓、托管、LP | Token Account owner 与 swap 现金对价 |
| 「上涨 = 真正大量新需求」 | 薄池冲击/LP 变化/重复交易 | 池储备、实际 Swap 对价、独立风险承担 |
| 「交易频率高 = 刷量」 | 正常套利/机器人执行 | 净库存、成本、跨池路径与相应对照 |
| 「Dev 清仓 = 无利益」 | 创建费/LP/其他合同收入 | 对应费配置、真实 entitlement/收款 |
| 「KOL 发帖 = 付费拉盘」 | 普通社交传播/自愿宣传 | 已证资助/合同/披露证据，而非推测 |
| 「统计上更常见 = 有因果作用」 | 筛选偏差、共同事件、测量混淆 | 活动匹配负对照、时间冻结及独立数据 |

专业调查不必要求每个问题无限搜证：只在**能改变重要结论**的地方追加来源，其他保持竞争解释并标 UNKNOWN。

## 对任何外部知识的最低出处结构

\`claim_id, source_url, source_type, source_version_or_date, scope, evidence_type, author_assertion_or_observed, assumption, counterexample, applicability, unknown, revised_at\`

允许 \`THEORY_SUPPORTED\` 作为可逆的研究假说依据；只有有可复查实际输出才能升级具体业务事实。系统不能因研究报告增多自动提高信心。

## 读数和异常时的反证清单

- 是 Token Account 还是其 owner？池 vault / PDA / CEX 有排除吗？
- Swap/transfer/LP/mint/burn 和同签名多动作有去重吗？
- Token 程序、版本、CPI、跨池、SOL/WSOL 是否正确解析？
- 数据库是否有未发现历史签名、补查队列遗漏、429/缓存/截断？
- 信号、采集与结果时钟是否被错误对齐？
- 母样本有没有包含未毕业、无人关注、失败 Mint；缺失结果是否被当负标签？
- 统计、机制、因果与可交易收益是否被混称同一件事？
