# 05｜通用 Meme 认知如何分化为专业应用，而不被任一应用绑架

> 本文件负责**迁移路径**，不把市场理解压缩成「怎么找钱包跟单」。通用知识即使不能当场产出跟单策略，依然可能对发币机制、异常辨析和市场认识有独立价值。

## 五种共享相同市场底层知识、却具有不同目标的应用

| 应用领域 | 真实的专业问题 | 调用的 Meme 通用知识 | 结果/证据形式 |
| --- | --- | --- | --- |
| 市场发现 | 哪些 Mint/池在当前观察条件下刚出现或发生结构性变化？ | 发行、生命周期、数据选择、时钟、价格/流动性 | 可观察的 Mint 事件与覆盖边界 |
| 单 Mint 调查 | 创建者、Holder、资金、库存、真实成交与 LP 是怎样变化的？ | 账户事实、经济主体、资金、库存、价格 | 可追溯的签名及竞争解释 |
| 跨 Mint 群体 | 参与者是否重复、分工是否演变、是否有资金/库存接力？ | 时序、行为网络、样本选择、公共设施反例 | 不同 Mint 可比较的角色候选图 |
| 经济机制研究 | 哪些市场规则、激励和行为反馈造成某种结果？ | 发行制度、费用、价格冲击、注意力、市场生态 | 条件性机制、可证伪推论、来源 |
| 跟单及其他决策 | 某种观察事前能否改变风险判断或后续行动？ | 上述部分 + 延迟、执行、退出、统计验证 | 候选分类、事前样本、成本及失败记录 |

**跟单是下游，不是定义市场的起点。** 同一张资金/库存图可以服务「解释发行经济」「识别样本污染」「复核风险」「发现新币」「研究群体」以及「跟单可复制性」。只有在确实问到跟单时才额外引入执行延迟、自己的资金规模、筛选算法和绩效验证。

## 三种知识层次不同，不能强行合并

**第一层：市场机制/协议知识**。例如 Token Account 与 owner 有别、某池的实际费用规则、LP 改变储备。这类知识帮助解释「发生了什么」与「在什么条件下可能发生」。

**第二层：调查方法/证据解释**。例如发现相似交易地址时检查共享公共 Hub、回补历史缺口、固定观测分母。这类知识帮助分辨不同解释。

**第三层：具体应用决策**。例如将某钱包只作为预警，不作为可复制买点；这是具体目标、约束、风险承受能力和事前数据共同决定的结果。

不必为了一个策略现在就证明所有市场理论的统计效应；但任何策略声称能可靠获利，必须另行取得相应的真实或严格纸上验证。市场理论足以支撑可逆的调查优先级，不足以自动支撑真实资产风险。

## Froggy / Blix 等工具在这个体系中的正确位置

- Froggy / GMGN / OKX：**市场观察和筛选来源**，不是整个市场的知识本体。
- Blix / 旧 Hermes / qb- / meme-：领域知识、业务场景、曾经使用的研究方法和历史错误的来源；原代码可参考、但不是所有结论的真值。
- ai-d：指导 AI **如何形成问题、检索、形成竞争解释、反馈和停止**；不替代领域事实。
- Gendan：将上述知识转换成**领域通用认知 + 随问题调用的专业应用方法**；不再从某个软件的功能菜单开始安排研究结构。

如果一个软件以后停更，通用 Meme 知识仍成立；应调整数据入口或该软件的可靠性记录，而不是重写市场理论。

## 应用前的最小「认知检查」

当未来有人问「这几个钱包值得跟吗」，AI 先确认通用层：
- 这是怎样的代币/池/市场阶段？
- 观察到的资产与行为是否真实（含账户、Swap、费用与时间）？
- 哪类参与者承担风险、怎样获取收益、有没有多钱包分工？
- 什么机制会产生相似数据而无需主观操控？

随后才加入跟单层：
- 它的历史优势能否在被观察到之后复制？
- 真实订单规模/成本/滑点/退出容量/失败样本是否改变结论？

这同样可以迁移为「查一枚新币的风险」「分析 KOL 与价格的关系」「追问为什么 AI 漏掉某个币」等场景。

## 下一轮正确的检验方向

不是继续添加第四种知识体系，而是**挑一个非跟单问题，检查新的通用认知能否改变答案**。

例如问题：「价格持续上涨、钱包数也增加，为什么池中的真实 SOL 承接并不明显？」以同一组可核验事实，对比「仅看涨幅/持有者数」和「市场+库存+流动性+观测」两种解释，核查：
1. 哪个错误认知被纠正？
2. 是否找到原本不知道的专业未知？
3. 下一项查什么可以最大幅度改变判断？
4. 有没有在现有工具中已经解决而不必开发的能力？

如果无法指出变化，应修订当前知识表达或方法，而不是再加标签。
