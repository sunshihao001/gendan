# RU-003｜真实钱包候选 × 交易子集 × 多钱包关系 × 跟随者账本：深层研究

**研究日**：2026-11-10。**定位**：俄语材料优先的 Solana Meme 跟单领域专属问题研究。**实证状态**：俄语原始字幕已逐段核对；俄语 Habr 原文已阅读；开源代码、测试、issue 和公开产品说明已核对；最小离线反例已运行。**没有**登录 Froggy、读取用户私钥、发起链上交易或完成真实 Mint 资金网络的签名级重放。本文绝不把公开标签、作者口述或模拟当真实跟单收益。

## 0｜核心结论：原研究对象太粗

过去习惯问：“哪个地址最聪明、哪个 ROI 最高、哪些地址一伙的？”这些是候选入口，不足以回答跟单的核心问题。

现在需要并行观察两个不同系统：

1. **链上经济系统**：真实钱包/Token Account/池/路由器/服务账户之间，哪些 SOL、WSOL、Token、swap、transfer、LP 与费用关系可以按签名核对？哪些行为反映资金承担、库存、风险、出货、跨 Mint 迁移？
2. **跟随者策略系统**：哪一份观察信号在什么时候到达？哪一条规则放行/禁止？买卖哪个策略仓位？若多个源钱包或多个镜像配置碰到同一个 Mint，何者有权触发卖出？订单是否实际可成交，预算和风险规则在当时是否允许？

**最小研究单元不是“地址”，而是：钱包 × Mint × 市场阶段 × 具体动作 × 首次可见时间 × 执行策略 × 共享仓位状态。**

这不是人为增加概念。俄语作者 Mark 的个性化过滤、Habr 镜像冲突、俄语开源代码的 owner 逻辑、Yuno 的回测选样错误风险，都指向这一不可省略的区分。

## 2｜俄语视频原文深读：不只看“215→5+2”

原视频：https://youtu.be/dxZqcCNAp3Y 。俄文字幕源来自用户上传的 txt；下文编号是**俄文短句从零开始编号**，不是播放时间戳。中文机翻不作为判定原始专业术语的依据。

### 2.1 候选母样本和首次筛除

- #73–79：作者展示 Froggy Premium 导出约 215 个候选地址，并另有“新钱包”显示区。**正确研究对象是一次带时间和筛选条件的导出批次**，不是全市场钱包总体。
- #82–88：作者看到只有两天的新地址就倾向跳过，偏好有更长交易历史的钱包。这是作者的经验性过滤，不等于新钱包一定不合格；新地址可能是旧策略的新执行地址。
- #94–120：作者不是只挑赚钱交易，也会打开亏损币、查看重复 ticker、是否抢买、实际进出仓。一个钱包重复出现同一 ticker 可能反映重复交易、同类策略、营销或不同 Mint 同名；需核实合约地址，不能靠 ticker 合并。
- #413–428：作者遇到看似高胜率但很短历史、曾亏约 70% 仍加仓的钱包，认为风险大。**风险研究应看损失严重度、重复加仓和资本暴露，而不只看 100% winrate。**

### 2.2 更核心的发现：筛的是同一钱包的动作子集

- #431–449：作者分析一个钱包更常交易低于若干市值阶段的 Token，考虑屏蔽过高市值的部分交易。这里的“市值与买入风格相匹配”是条件假说。
- #519–540：作者解释自己倾向限制钱包“高市值区的亏损交易”或“太小入场金额的交易”，让复制程序只放行被认为可靠的 entry。**但这种裁剪若从全部历史输赢反推，就存在选择性拟合。**
- #645–658：作者演示在 TradeWiz 设置最低市值过滤，视频口述示例约 11,000。该数值不是建议，也不是有样本外依据的普适阈值。
- #2900–2925：作者示范 10 笔历史交易只想取其中 3 笔，并以历史达到的 4–8 倍等结果说明筛选看起来更好。**这正是“后验选择盈利子集”的危险样本**：除非事前冻结的规则能在后续未知交易重现，否则这仅是事后解释。

因此不是“按视频参数配 TradeWiz”，而是**把作者的筛选直觉翻译为可证伪的规则，并禁止历史结果参与同一批次验证**。

### 2.3 软件配置是研究变量，不能照抄

- #3020–3050：作者关闭 Turbo，并描述 Turbo 可减少部分条件检查、提升响应速度。这是作者对软件机制的说明，未核对具体版本代码；不能由此断言开启 Turbo 是安全或一定更快。
- #3052–3095：作者演示仓位百分比、单次预算、总支出限制、每币最多买入次数，倾向不要无限加仓。账本上“Copy 100%”与“下固定 0.1 SOL”是不同维度：前者可能是跟随目标金额比例，后者是每次预算/金额上限，取决于具体 UI 定义。
- #3100–3120：作者启用复制卖出，提到较高的买/卖滑点容忍度（约 30% / 50%）。**滑点容忍度 ≠ 实际成交损失；这些高容忍度不能作为我们推荐的设置。**
- #3134–3157：出现目标最小买额约 0.5 SOL 和作者设置下单阈值留费余量；还展示若涨至 100%/300% 逐步出售一部分的止盈方案。这些是作者在视频中的具体配置，与“是否复制源钱包卖出”和“新高以后还能不能成交”存在不同策略假设。
- #3169–3190：针对其他钱包再配完全不同的买额区间和分批止盈层级。**一个软件任务不等于一个经过验证的策略**；不同任务不能为了得到总体 ROI 而事后合并赢者、删掉输者。

### 2.4 第十天回访：这是检验长期有效性的线索，不是盈利证明

- #2190–2253：第一批约 5 个准备复制＋2 个只追踪；重新打开某个已选地址时，作者忘记入选原因、发现难以理解的交易结构而删去。**初选理由必须原位保存，否则不能独立复审。**
- #3316–3343：约 10 天后回看，作者称有 2 个地址把余额提走，剩下约 7 个；其中实际出现明显跟单交易的只有少数（口述一号与七号）。不能把未活跃钱包从最初候选的成功率分母隐去。
- #3364–3383：作者口述个别地址贡献约 0.25 SOL、0.11 SOL，并说自己的总执行账户混入其他人的交易；他为展示跟单结果保留跟单相关交易。**源地址绩效、被展示的跟单子集、整个执行账户净值和出入金，四者必须拆开。**
- #3400–3443：作者展示一笔约 -90% 的币，并反思是否应该增加止损。出现严重亏损交易是反证线索，不能只引用作者自称正收益。
- #3464–3516：他展示源地址与自己地址在少数交易中的 Slot/区块位置，声称某次相差约一个或数个区块；**单次截图不能推断全局延迟分布，也不能证明每次能以同等价格成交。**

## 3｜另一条俄语实证线：Habr 的两种“冲突”必须分开

俄语原文：2025-05-29 https://habr.com/ru/articles/913768/ 。

**首先纠正上一轮的一项归纳错误**：Habr 原文表述是“两个镜像连接到同一个钱包”（два зеркала, подключённые к одному кошельку），不是能确定“两只不同的源钱包”。它描述镜像 A 持有某 Token，镜像 B 提前卖出同一 Token，使实际账户亏损约 180 美元；A 后来才按其逻辑卖出。这是**同源钱包的多配置/多镜像可能争夺同一共享持仓**的作者案例，不能直接拿它证明两个不同源地址互相冲突。

但两种风险可以作为**两个不同的研究命题**：
1. **同一源钱包、多镜像配置共用执行账户**：策略配置重叠、部分卖出行为、手工买卖可能争夺同一个 Token 余额。Habr 直接描述此情境。
2. **不同源钱包、同 Mint 重复信号进入同一执行账户**：理论上也会冲突；anchoys1337 开源程序使用“第一个主导钱包 owner，其他跳过”的源码规则处理。它是另一个由软件设计反证支持的问题，不能把第一种用户自述误当第二种实测。

同一篇 Habr 作者还自述：
- HFT 约半分钟 100+ 笔，他的预算无法承接；套利目标镜像晚约 30–50 秒，机会失效；
- 低频地址约每天 1–2 币，能更有时间检查；作者声称 1.5 个月约 +$2,000，但约 $3,500 的获利集中在 4–5 笔，另有两币约 -$1,500；
- 手工持仓与跟单 Bot 共用 Token 时，自动卖出也可能干扰手工策略。

这说明同一历史“盈利”背后，**尾部输赢、容量、频次、退出动作和策略权属**可能比平均胜率更重要。此文不提供可独立审计的交易明细，因此只是 AUTHOR_REPORT。

## 4｜链上资金网络与跟单策略冲突是两张完全不同的图

### 4.1 链上资产/经济角色图：研究某个钱包为什么这样交易

~~~mermaid
flowchart TD
    S[可能的资金来源 S] -->|原始SOL转账签名| A[早期买入者 A]
    A -->|DEX真实Swap| P[池与报价资产]
    A -->|Token Transfer| B[接收者 B]
    B -->|后续DEX Swap| Q[可能的卖出现金流]
    B -->|可能的资金转出| C[另一Mint参与者 C]
    H[共享CEX或路由器] -.公共Hub不能证明同控.-> A
    H -.公共Hub不能证明同控.-> C
~~~

需要分别建立：某签名内 Token Account→owner、fee payer、authority；某个 Swap 中真实双向净资产变化；Token 转移的账户与当时 owner；池子和公共服务节点；后续跨 Mint 资金是否时间可达。多跳可达不等于同一笔 SOL 的唯一去向，也不等于同一经济控制者。

尤其需区别**地址角色和真正收益归属**：A 可为买入地址、B 为转仓接收/卖出地址、S 为资金提供者、C 为另一个交易策略主体。把 B 卖出利润直接计入 A 的 PnL，必须另有归属证据；不然宁可 UNKNOWN。

### 4.2 跟随者交易/共享仓位图：研究复制它为什么可能失败

~~~mermaid
flowchart TD
    A[源信号A] --> G[过滤与观察时钟]
    B[另一镜像或另一源信号B] --> G
    G --> R[策略归属规则与重复Mint冲突]
    R --> L1[策略账本 A]
    R --> L2[策略账本 B]
    L1 --> P[跟随者实际Token余额]
    L2 --> P
    P --> X[真实入场价格/费用/卖出容量/退出]
~~~

即使 A/B 在链上完全不相关，在跟随账户里也可能争夺同一持仓。反过来，即使 A/B 在链上属于一个经济群体，如果监控不到可复制的交易，也不值得直接复制。两张图需通过**Mint、事件签名、时间和真实余额**连接，而不是合并成一个“相关度打分”。

### 4.3 最小三类图谱断言

| 观察事实 | 专业允许推断 | 禁止的跃迁 |
| --- | --- | --- |
| 多个地址同 Slot/同池买 | 时间、执行位置接近；可能共用事件或工具 | 一定是真 Jito Bundle、庄家、内幕 |
| A 将 Token 发给 B，B 后续卖 | Token 转移与后续 B 的 swap，可观察卖压与库存变化 | A/B 同控、B 全部售出 Token 一定来自 A |
| A/B 都发出跟随 Mint-X 的信号 | 需要检查策略仓位冲突/重复买入 | 二者在链上必定关联，或两次交易可独立计盈亏 |
| 某地址盈利集中在首槽交易 | 历史来源很早，需测首次可见时间 | 用当时低价做跟随者成本 |
| 机器人多次提醒同一签名 | 多源订阅/回补可能重复，需要去重 | 多笔独立买入或多个盈利机会 |

## 5｜本轮新增源码级反证：现成程序也会定义错误研究对象

### 5.1 Anchoys1337：多目标 owner 规则有价值，但“DEMO”不等于可执行市场

俄语 README 和源代码：https://github.com/anchoys1337/solana-wallet-behavior-analysis

- strategy.py 使用一个 Mint 一个主导 owner 的方式，其他跟踪钱包买卖经 NOT_OWNER 跳过，重复买经 TARGET_RE_BUY 跳过；tests/test_owner.py 有对应测试。
- engine.py 对真实买入设置信号超时、启动前旧信号、开放仓位数和当日损失的门禁，但 DEMO_MODE 直接跳过这些真实风险条件；历史回补可进模拟。
- executor.py 的 PaperExecutor 以传入的源交易/估计价格记录虚拟成交；README 指出滑点模拟默认不开。这个“Paper PnL”不能直接作为当时实际可执行的跟随收益。
- Token 完全转出和真实卖出在程序状态上可以触发不同处理，某些风险规则可能使跟随仓位关闭。这是**镜像策略动作**，不应反写成“源地址卖出”。

**可复用的是问题分解和测试思想**，而不是直接安装其执行程序。所有代码审计状态 CODE_READ_NOT_RUN。

### 5.2 Yuno Research：真实多策略框架、已有失败结果以及可复算的重叠反例

项目：https://github.com/yuno-research/solana_copy_trading

- README 把 First-Buy-First-Sell (FBFS) 作为地址交易形态的简化研究方法；score_wallets.py 依赖已关闭 FBFS 仓位汇总排行。这样做能简化数据，却可能遗漏部分卖出、转仓与始终未关闭的风险头寸。它是代理标签，不是完整钱包经济利润。
- create_backtesting_positions_for_wallets.py 支持 buy_delay_seconds（默认示例 1 秒）、不同流动性过滤、按历史时间 join_asof 取价格、de_duplicate_positions 防同 Mint 重叠。
- 该文件 de_duplicate_positions 分支对 entry_timestamp 排序，并用 exit_timestamp.shift(1).over(token_id) 只对比前一个**原始**候选的退出时间；如果前一个候选本来已经被过滤，仍可能错误允许与更早的长仓位冲突的新候选。
- 本轮专门用不包含交易或真实钱包的最小合成条件复算：Mint-X 的 A[0,100]、B[10,20]、C[30,40]。直接对比前一原始行时 A、C 会通过；若“该 Mint 不能存在同时开放的两个策略仓位”为政策，则 C 应被拒绝，因为 A 仍持有。可运行脚本在 research/labs/study003_overlap_repro.py。
- **这只证明上述源分支判断存在边界案例，不等于完整 Yuno 产品已在真实交易里发生该缺陷**。项目 README 也表明 de_duplicate_positions 是可选功能，并非所有策略默认开启。
- 更有价值的作者自我反证：公开 Issue #10（2025-12-01）明确提出，先排序、遗传优化、再在未见过的新窗口重排回测的路线**当时仍未得到盈利结果**，并询问是否过拟合或研究方法不对。这是比营销“最佳参数”更重要的原始研发反馈。链接：https://github.com/yuno-research/solana_copy_trading/issues/10 。
- Issue #9（2025-10-02）承认在 Pump.fun 卖出时有未成功且反复重试的问题，属于作者公开记录的执行故障，不能因为仓库含生产代码就称卖出总能完成。链接：https://github.com/yuno-research/solana_copy_trading/issues/9 。
- Issue #5 提议研究“某钱包买入后 10 秒内买单数相对前 10 秒的变化”，间接提出**被跟钱包自身可能改变后续价格或吸引更多追随**的问题，仍是想法而非已证明指标。

本项目研究 002 已核实：公开 find_optimal_P_cv() 每轮只在 70% 训练样本选择阈值，未在剩余 30% 评价策略结果；匿名样本 80 行的存储 roi_pct 均不能按其公开价格列和公式一致复算。样本明确匿名替换，不能指控作者真实数据造假。源程序以入场后的历史峰价计算是否达到止盈阈值，属于“历史可达上限”，不等于跟随者在那个时点可以成交。

三个项目合起来揭示：**很多看似不同的高性能策略，其实回答的是“历史回放里哪个分数更高”，而非“当观察者收到信号时，我还能以什么成本买卖、多个策略会不会冲突、亏损单能不能出掉”。**

## 8｜怎样才算真实验证“只复制特定交易子集”

### 8.1 研究前冻结，不把历史赢家当未来证据

设一批候选来自 Froggy/OKX 的真实导出，在观察开始 T0 冻结以下字段：

- 来源原文、原始工具版本、候选全量/排除量、当时钱包名和完整地址；
- 最早被发现的时间、钱包之前全部可访问币样本（含失败币）、原始 PnL 口径；
- 策略 ID、属于源钱包还是多个镜像配置、资金与 Token 执行账本是否共享；
- 待研究的过滤变量（入场币龄、市值、金额、Slot、流动性、重复买、首次可见时延），**在 T0 前规定范围与否定条件**；
- 仅观察/纸上测试/跳过及原因、可否知道 Token 的后续入池及卖出证据；
- 数据缺失、公共服务中心、Token Account owner 不明及失败解析的数量。

不能拿未来才知道的“达到 ATH”决定过去在 T0 是否入选；历史可能有最高价但下单失败仍需保留。

### 8.2 四组比较，必须用同一观察者时钟

A. **基准**：按钱包整体历史绩效入选、所有可观察买入；相同固定预算和延迟。
B. **动作子集**：按钱包预先冻结的阶段/买额/持有方式过滤；记录它排除的全部信号。
C. **B + 网络反证**：发现源钱包为库存转仓/服务节点/高拥挤薄池/首槽不可复制时，只改变 WATCH/PAPER-TEST 判断，不能用无证身份标签在历史中强制剔除。
D. **B + 策略冲突约束**：同 Mint 预定义一个主导 owner 或不同策略逻辑分账；记录原本会发生的重复买卖、提前出仓和人工交易干扰。

**同一源钱包触发的不同条件镜像**与**不同源钱包触发同 Mint 信号**分别统计。不同钱包在同一 Mint 的多次信号不应被当成完全独立样本。

### 8.3 比较不是“最后净利润一个数”

每笔记录 source-chain-slot、T_provider_seen、T_user_seen、T_quote、价格证据、路由、预算可用性、可成交规模、预期冲击/费用、是否失败、最终可卖、是否出现转仓/未知退出。需要分别报告：

- 包含跳过/延迟/失去报价的**完整信号数、放行数、真正可执行数**；
- 可执行样本上净损益、全部候选样本对应的最终资金收益（包括没成交/锁定的现金）、胜负分布及大亏尾部；
- 单一巨额赢家占比、未售 Token 价值估计误差、连续不活跃钱包比例；
- 延迟敏感性：T_seen/报价滞后 0、1、2、5 Slot 等均为**研究假设场景**；不可将“事后 T_chain 的最优价格”当 0 延迟现实；
- 策略冲突引起的提前卖出、重复买入/重复计收益、订单失败和漏事件；
- 按发行阶段、流动性、时间窗口、独立经济群体分组的稳定性，而非随机打乱相似交易让训练测试泄漏。

**缺历史真实报价**不能自动用未来高点补齐。对数据不完整样本明确 UNKNOWN/MISSING，不以删除失败样本抬高分数。

### 8.4 必要的三组反证

- **时间反证**：同钱包的利润是否集中于我们首次可见前已完成的首槽/极速交易？把 T_chain 换成 T_seen 后优势是否消失？
- **行为反证**：钱包高 Win Rate 是否靠一次爆赚、少量已卖币，或转去另一个地址后才卖？样本分母、库存和角色一改结论是否反转？
- **网络反证**：看似多钱包协同是否其实共用 CEX、费支付或路由程序？独立匹配机器人活动的对照钱包是否也有相似同期交易？如果是，取消“同控”标签，而不是保留高置信度分数。

## 9｜最小离线反例实验：能说明什么，不能说明什么

脚本：[study003_overlap_repro.py](labs/study003_overlap_repro.py)。仅用标准库、不联网、不使用密钥，只模拟“时间区间筛选”和“两种不同价格下的跟随者净收益”。本轮实际运行通过。

**反例 A：同 Mint 重叠去重**
- Mint-X：长仓 A[0,100]、短仓 B[10,20]、后续短仓 C[30,40]。
- 仅看前一原始候选是否结束时，A 和 C 都会被接受；但 C 仍落在 A 的持有期，违背“不允许同 Mint 同时持有两个策略仓位”的预设。
- 这用于确认一条**特定算法语义问题**，不能外推为所有产品都失败。

**反例 B：历史源钱包盈利，跟随者可赔钱**
- 纯构造数字：源钱包 1.00 买、1.50 卖，账面 +50%；
- 跟随者观察到买入时 1.40，离场仅能 1.35；两侧各 1% 假定成本，结果约 -5.48%。
- 未计订单实际冲击、池深度、税费、未成交和最大损失，**仅说明同一 Mint 并不意味着同一收益**。

这两个反例让本项目避免“提交更多漂亮理论，却连一句软件去重说明都没有核查”的旧问题。

## 10｜本轮的五项认知增量、三个不应过度延伸的结论

**新认识**
1. 观察源钱包的属性，不能代替研究“跟随者的可执行动作子集”。
2. 链上钱包关联和跟随者组合仓位冲突是不同的两张图；两者任何一张缺失都会误读收益。
3. 源钱包已卖/已转仓、机器人策略决定清仓、跟随者真实卖出是三个独立事件。
4. 成熟软件的回测也可能含有源价格借用、模拟与实盘门禁不一致、区间去重缺陷；需要看原代码和失败 Issue，而不是看发布页星级。
5. 作者公开承认未盈利或回访里出现长时间不活跃、严重亏损，通常比示范“赚了几倍”的图片更能改变方法。

**不能由本轮断定**
- 俄语 Mark/Froggy 的个性化过滤具有统计上正的、可持续的交易优势；
- Yuno 的整个产品在当前环境真实运行有缺陷或一定亏损；只查到具体源分支与当时 issue；
- 三个公开钱包/Mint/签名属于同一资金关系。链上签名未取得时必须保留 UNKNOWN。

## 11｜下一轮优先实验入口（不是再开新目录）

唯一 P0 是取得一组**可合法只读获取的真实候选与后续事件**：优先真实 Froggy 导出（不需要任何助记词）；如暂不可得，先用公开钱包 5CcLBq… 或公开 Mint FRpTy… 寻找可回取的交易签名。取得一笔完整签名链后，比较 A/B/C/D 四种事前可表述规则；没有实际后续报价就停止在 SOURCE_ONLY，不继续制造收益数字。

旧知识路由：只有需要解释 Token Account/owner、WSOL/CPI、资金路径、库存/多跳和价格冲击时，才按需读取 [原 Blix 钱包研究](https://github.com/sunshihao001/grok/blob/blix/knowledge/methods/key-wallet-investigation-brief.md)、[多跳专项](https://github.com/sunshihao001/grok/blob/blix/knowledge/references/multihop-funding-evidence-audit.md) 和 [ai-d 问题发现](https://github.com/sunshihao001/ai-d/blob/main/research/2026-11-07-problem-driven-unknown-discovery.md)。
