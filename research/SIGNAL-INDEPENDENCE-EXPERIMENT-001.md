# 实验 001｜“三个钱包同时买入”不等于三个独立交易信号（2026-11-10）

> 研究问题：把 Gendan 现有的“共享资金源候选 / 同槽买入候选”研究，真正用于解释跟单群体信号，而不是只生成关系图。本实验只检验**判断是否发生变化**，不检验任何盈利策略。
>
> **数据状态：SYNTHETIC_FIXTURE_ONLY；并非真实链上钱包、Mint、成交价或 Jito Bundle。** 不导入密钥、不签名、不下单。当前证据不足以给出实际控制者数量。

## 1. 实际复用的现有资产

- 原始能力：[Gendan engine](../gendan/engine.py) 的 `analyze()` 已按交易事件区分 `SWAP_BUY_EVENT`、`SAME_SLOT_CANDIDATE`、`SHARED_FUNDER_CANDIDATE`、转账与接收后卖出候选；`SAME_SLOT_CANDIDATE` 当前限定在输入 `launch_slot`。
- 新的轻量只读对照：[tools/signal_independence.py](../tools/signal_independence.py) 只在原引擎输出上增加**观察时点过滤、原始地址数、候选关系和假设归并情景**。不再开发一套链上解析器。
- 新增显式合成输入：[data/signal_independence_demo.json](../data/signal_independence_demo.json)；保留旧 [data/demo_case.json](../data/demo_case.json) 原样。旧案例只有**2个同槽买入者**，不能冒充三钱包案例，因此独立新增第三买入者 W_D。
- 新增测试：[tests/test_signal_independence.py](../tests/test_signal_independence.py) 包括：未来事件隔离、3地址与2假设组、只有同槽而无共同资金源不能减少情景票数、晚到信号不可穿越过去时点、重复事件不增加买入数、无资金边不等于独立等。
- 判断边界来自 [Million owner规则及源码风险审查](MATURE-PRODUCT-MECHANISMS-20261110.md)，不是盲目照搬其 `ownerId`。

## 2. 场景和可重复命令

观察时点 `T=2026-11-09T01:03:00Z`，买入窗口10分钟。合成事件：

| 事件 | 时间/Slot | 钱包关系 | 截至 T 是否已经可见 |
| --- | --- | --- | --- |
| F 向 W_A 发送 SOL | 01:00 / 1000 | 已观察资金边 | 是 |
| F 向 W_C 发送 SOL | 01:01 / 1001 | 已观察资金边 | 是 |
| W_A 买入 | 01:02 / 1003 | 第一个买入者 | 是 |
| W_C 买入 | 01:02 / 1003 | 与 W_A 同 Slot | 是 |
| W_D 买入 | 01:02:25 / 1004 | 第三个买入者，暂无已见资金边 | 是 |
| W_A 给 W_B 转 Token | 01:15 / 1030 | 未来转仓事件 | **否，不得用于 T 的判断** |
| W_B 卖出 | 01:30 / 1050 | 未来卖出事件 | **否，不得用于 T 的判断** |

在仓库根目录运行：

```bash
python -m tools.signal_independence data/signal_independence_demo.json --at 2026-11-09T01:03:00Z --window-minutes 10 --out output/signal_independence_demo.json
python -m unittest discover -s tests -v
```

不需要 RPC/Helius/钱包/交易账号。该工具直接调用既有 `gendan.engine.analyze()`。自带测试必须在同一仓库根目录运行。

## 3. 对照结果及其真正含义

| 项目 | 直接按地址计票 | 联系现有 Gendan 资金/时序证据后 |
| --- | --- | --- |
| 可见买入地址 | 3：W_A、W_C、W_D | 仍是 3 个可见地址 |
| 额外证据 | 无 | W_A 与 W_C 有共同资金来源 F，同 Slot 买入 |
| 若强行假设“共享出资即同一操作者” | 默认3个地址均单独计 | `{W_A,W_C}` 与 `{W_D}`，**2个假设群组** |
| 真实独立经济主体数量 | **UNKNOWN** | **仍然 UNKNOWN** |
| 可支持的业务表述 | “3个地址买入” | “3个地址买入，其中2个具有资金与同槽关联线索；不能证明3个独立信号” |
| 策略行动 | 不能仅凭此决定买入 | `WATCH_OR_INVESTIGATE`，不提升为已验证独立群体信号 |

**关于“2”的严格限定：** 这是在一个*明确且很强的假设*下做的敏感性情景计算，不是实际人数、不是准确下界，也不能变成已证实的 Owner 聚类结果。共同资金来源可能是 CEX/路由器/服务账户；W_D 没有关系边也可能只是数据未覆盖。未经充分证据，**不能确定任何一对钱包是独立控制者**。

### 信息价值究竟体现在哪里？

此前只有“3个地址同时买”。现在能明确提出并定位一个可复查的风险：W_A 与 W_C 的共同出资可能导致一人多票；同时提醒不能靠关联启发式就强并人头。

这是一项**认知/判断增量**，并未证明这种过滤方式提升策略的真实收益。若要证明后者，必须拿未来未知结果的真实信号、可报价时间、买卖净流和失败样本比较。

## 4. 这轮实际检查了什么，没检查什么

- **已完成**：GitHub 3个新增源码/输入/测试文件保存并回读；在同一合成输入上执行独立 JS 离线复算，断言结果 3 地址 / 2 假设组 / 5 条 T 前已可见事件 / 1 对同槽 / 1 对共源；在本地 Python 对对照函数进行纯逻辑检查，断言3/2、无共源时3/3、真实主体 UNKNOWN。
- **尚未完成**：在拥有**完整仓库源文件**的本地/CI 环境运行全量 `python -m unittest discover -s tests -v`，尤其新测试实际导入 `gendan.engine.analyze` 的集成路径。**不要称“新集成测试已全部通过”**。
- **未完成且本实验无意完成**：真实主网签名、各钱包共同控制证明、真实多源同Mint信号到达时间、前向纸上净收益、AI 自动执行。

## 5. 下一项应该怎么判断（不自动升级为强制路线）

**后续候选 A：** 补一个“公共出金 Hub / 大量钱包同步交易”对照，检验若直接按共享资金合并会怎样漏掉真正独立的交易者；若有可靠的实际签名、交易所或服务地址证据，优先使用它而非继续合成案例。

**后续候选 B：** 将候选关系与同一时间窗的买卖净流、各钱包交易角色、池流动性结合，检验“多个买入地址”究竟可能意味着买盘、洗量、转仓还是退出流动性。当前数据缺口是可核对的真实原始 Swap/Transfer 和时间覆盖。

**后续候选 C：** 切到与个人操作直接相关的“钱包风格 × 跟随者延迟/退出/费用”，用成熟软件模拟功能验证；不必先把群体归因做成完整产品。

**当前建议**：先核验仓库新集成测试，再根据用户后续目标在 B、C 或真实钱包调查之间选择。若发现已有成熟产品可以可靠提供结果，优先直接复用，而不是继续造群体聚类系统。

> 本实验是“AI 让两种专业能力产生可复查的判断增量”的小试，不是承诺必须走向群体信号产品；研究价值仍要回到用户所追求的跟单/情报/策略目的判断。
